How it works

1Describe

Muse Spark drafts a structured robot spec from your plain-language description.

2Validate

Engineering checks catch impossible or inconsistent numbers before anything is simulated.

3Twin

The spec becomes a digital twin that runs headless in Gazebo Sim.

4Gate

A measured motion test grades the twin against fixed thresholds — pass, marginal, or fail.

The Gate

The twin is commanded to drive 1 metre and turn 90 degrees. Odometry measures what it actually did, and the difference between commanded and measured is the grade.

MeasurementPassMarginalFail
Distance error≤5%5–10%>10%
Heading error≤5°5–10°>10°

Thresholds are printed on every report and never quietly loosened.

Take a robot apart

Every RobotForge spec becomes a take-apart kit of simple, 3D-printable parts (robotforge cad). This viewer lays the kit out exactly the way the kit's own assembly file does — same wheel positions, same axle height, same deck placement — straight from the robot's spec file. Drag Explode to spread the parts, and click any part to learn what it is.

0 mm

Side view — the robot's length runs left (rear) to right (front); height is up. Ground is z = 0 and wheel axles sit at wheel-radius height, as in the kit assembly.

Top view — length left–right, width up–down. Explode moves the wheels outward here, exactly like the kit's explode_mm.

Pick a part

Click any part in either view. You will get what it is in plain words, its key dimensions from the spec, one beginner tweak, and a print suggestion (labeled as a suggestion).

This is a layout viewer built from the spec's numbers, not a CAD render. The printable files themselves are generated per robot by robotforge cad — one OpenSCAD file per part, so each part can be opened and edited on its own. The generated kits are browsable on the Parts Kit page.

Gate evidence
